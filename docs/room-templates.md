# Room templates

A template describes everything about a room's layout: where the shared origin is, the
furniture, the seats, the whiteboards, the objects on the table, the environment and the rules.
Rooms pick a template (`rooms.list[].template`), and hosts can switch templates in the app.

## Built-in templates

| id | Layout | Seats | Boards |
|---|---|---|---|
| `standard` | rectangular table, board at the end | 7 | 1 |
| `round-table` | round table, seats in a circle | 6 | 1 |
| `workshop` | long table, a board at each end | 8 | 2 |
| `presentation` | no table: presenter spot, two rows of chairs, a large board | 9 | 1 |

Their full definitions are in [`server/config/templates.ts`](../server/config/templates.ts) and
double as examples (they use the same format as config files).

## The shared frame

All positions are in the room's **shared frame**: meters, +Y up, right-handed. Where its origin
is depends on the `anchor`:

- `anchor: { kind: table, floorOffset: 0.72 }` — the origin is the **centre of the main table
  top**, 0.72 m above the floor. "Place here (1 pt)" puts this point on your real table, and the
  two-point calibration puts it between the two touched points.
- `anchor: { kind: floor, floorOffset: 0 }` — the origin is on the floor (rooms without a table).

Angles are degrees. `yaw: 0` faces **-Z**; positive yaw turns counter-clockwise seen from above.
Seats without a `yaw` face the origin (or `lookAt: [x, z]`).

## Writing a template

```yaml
templates:
  - id: product-demo
    extends: round-table          # start from another template (optional)
    title: { en: Product demo, ja: 製品デモ }
    environment:                  # merged with the parent
      background: "#1f2430"
      floor: plain                # grid | plain | none
      floorColor: "#2b3140"
      light: 1.2
    addObjects:                   # appended to the parent's objects (`objects:` replaces them)
      - id: drone
        kind: model
        position: [0, 0.02, 0.4]
        rotation: [0, 45, 0]      # Euler degrees (X, Y, Z)
        model: { src: /room-assets/drone.glb, scale: 1.2 }
    rules:
      maxParticipants: 6
      permissions: { clearBoard: hosts }
```

| Field | Notes |
|---|---|
| `anchor` | see above |
| `tables[]` | `shape: rect` (`width`, `depth`) or `round` (`width` = diameter); `height` above the floor; `x`, `z`, `yaw`, `color` |
| `seats` | a list of `{ x, z, yaw? , lookAt? }`, or `{ auto: { count, radius, startAngle } }` for a circle around the origin |
| `boards[]` | `{ id, x, y, z, yaw, width, height, background }` — `y` is the board centre; yaw 0 faces +Z |
| `objects[]` / `addObjects[]` | `kind: cube \| sphere \| cone \| torus \| pen \| model`, `position`, `rotation`, `scale`, `color` |
| `rules` | `maxParticipants`, `voice.enabled`, `permissions.{clearBoard,resetObjects,editSettings}` |

When extending, `environment` and `rules` are merged; `tables`, `seats`, `boards` and `objects`
replace the parent's lists (use `addObjects` to add). Ids must be unique within a template.
The number of seats limits how many people fit in the room.

Pens write in their own `color`; give each seat a pen nearby.

## Custom 3D models

`kind: model` objects load a glTF 2.0 file (`.glb` recommended, Meshopt compression supported):

```yaml
- id: engine
  kind: model
  position: [0.2, 0, -0.1]
  model:
    src: /room-assets/engine.glb    # or https://models.acme.example/engine.glb
    scale: 0.5
    grabRadius: 0.2                 # optional; computed from the model bounds otherwise
```

- Files under `assets.dir` are served at `/room-assets/`; https URLs must come from an origin in
  `assets.allowedOrigins`.
- Browsers refuse models over `assets.maxModelBytes` (25 MB by default), over 500k triangles or
  with textures above 4096 px, and show a placeholder instead.
- Models keep their own units (glTF uses meters); use `scale` to fit them on the table.
- Everyone can grab and move models like any other object.

A sample model is generated by `npm run make:sample-model` (`examples/room-assets/drone.glb`).

## Testing a template locally

```bash
COLO_CONFIG=my-config.yaml npm run dev
```

The server reports template errors (unknown parent, cycles, duplicate ids) at startup and on
reload. As a host, open **Room settings** to switch the layout of a running room.
