# 設計

## 全体像

```
 ┌────────── 端末 A (Quest / Android XR / PC) ──────────┐        ┌──── サーバー (Node) ────┐
 │ WebXR 参照空間 (local-floor, 端末ごとにバラバラ)      │        │  Room (ルームごと)       │
 │   └─ sharedRoot  … 行列 M_A = ローカル ← 共有         │  JSON  │   peers / poses          │
 │        ├─ テーブル・ホワイトボード                     │◀──────▶│   objects (+ owner)      │
 │        ├─ 共有オブジェクト (ObjectManager)             │   WS   │   strokes                │
 │        └─ リモートアバター (AvatarManager)             │        │  検証・レート制限・心拍  │
 │             └─ 頭に PositionalAudio (相手の声)         │        │  rtc-* の中継            │
 └──────────────────────────┬────────────────────────────┘        └──────────────────────────┘
                            │ 音声: WebRTC P2P (参加者ごとに 1 本、シグナリングは上の WS)
                            ▼
                    端末 B, C, … (同じ構成)
```

この設計の中心は、**ネットワークには「共有座標系」の値しか流さない** ことにある。端末ごとの座標系の違いは、各端末の `sharedRoot` の行列 `M` がすべて吸収する。

- 送信: `共有 = M⁻¹ · ローカル`
- 受信: 共有座標系の値を、`sharedRoot` の子としてそのまま置く

## 共有座標系 (shared frame)

右手系・Y 軸が上・単位はメートル。原点はテーブル天板の中心、+X はホワイトボードの方向 (`shared/protocol.ts`)。

| モード | 入力 | M の決め方 | 用途 |
|---|---|---|---|
| 仮置き (`auto`) | XR 開始時の頭の姿勢 | 頭の正面、席までの距離に天板を置き、天板の高さは目線 − 0.5 m (0.6〜1.05 m に収める) | 入ってすぐ使える |
| 1 点 (`one-point`) | 机の中心をタッチ | 原点 = タッチ点。「原点 → 頭」の水平方向を、共有座標系での自分の席の方向に合わせる | **リモート**。各自の実物の机に合わせる |
| 2 点 (`two-point`) | 同じ物理点 A, B を同じ順でタッチ | 原点 = 中点、+X = A→B の水平方向 | **同室コロケーション**。物理空間と一致する |
| デスクトップ | なし | ローカル原点の 0.72 m 上を天板にする | PC / スマホ参加 |

- 実装は `src/sync/sharedFrame.ts` にある。数式の正しさは `test/sharedFrame.test.ts` で確かめている。
  - 「異なる座標系の 2 端末が同じ 2 点をタッチすると、物理的な同じ点が同じ共有座標になる」ことを検証している。
- キャリブ後は、対応端末なら `XRAnchor` を張る。毎フレームその姿勢で `M` を更新するので、トラッキングの再ローカライズでズレない。
- 1 点モードで席を使う理由: 2 人がそれぞれ自分の机の手前に座って 1 点キャリブすると、2 人とも共有空間の同じ側に座ってしまい、重なって見える。サーバーが割り当てる席番号 (0 と 1 は向かい合わせ) を使って回転を決めることで、リモート同士がテーブルを挟んで向かい合うようにしている。
- 同室 ID (`space`) が同じ AR 参加者同士は、相手の実物が見えている。そのためアバターの頭と手を隠し、名札だけを表示する。

## 同期モデル

### オブジェクト (`src/sync/objects.ts`, `server/room.ts`)

所有権 (ロック) 方式で同期する。

1. 掴んだ瞬間、自分の物として**楽観的に**動かし始め、`grab` を送る。待ち時間はゼロ。
2. サーバーが先着順で `owner` を確定し、全員に配る。
3. 負けた側は `owner`、または `grab-denied` (サーバーの姿勢つき) を受け取って手を離し、その姿勢に戻る。
4. 掴んでいる間は所有者だけが約 30 Hz で `move` を送る。サーバーは所有者以外の `move` を捨てる。
5. `release` には最終姿勢を付ける。持ち主が切断した場合、サーバーは最後の姿勢のまま所有権を解放する。

所有者でない端末は、受け取った姿勢に指数平滑化 (`1 − e^(−rate·dt)`) で追従する。フレームレートに依存しない。2 m 以上離れていれば瞬間移動させる。

### アバター

- 頭と左右の手 (グリップ姿勢) を 20 Hz で送る。サーバーは中継し、最新値だけを保持して途中参加者に渡す。
- PC 参加者の場合、頭 = カメラ、右手 = ドラッグ中 / 描画中のカーソル位置。

### ホワイトボード (`src/board/`)

- ストロークは**ボード上の正規化座標 (u, v)** で表す。ボードの大きさや置き場所が端末ごとに違っても壊れない。
- 送信は 3 種類: `stroke` (開始) → `stroke-pts` (40 ms ごとにまとめて追記) → `stroke-end`。
- 書いた本人の画面には即座に描く。他の人には差分だけを CanvasTexture に描き足す。テクスチャの転送は 30 Hz までに抑えている。
- 書ける方法は 3 つ:
  - XR: ペンを持ち、ペン先がボード面から 8 mm 以内 (裏側は 5 cm まで) に入っている間だけ書く。
  - XR: 何も持たずに、レイをボードに向けてトリガーで書く。
  - PC: ボード上でドラッグする。

### 音声 (`src/voice/`)

少人数向けの **WebRTC P2P メッシュ** で、音声に参加している相手ごとに `RTCPeerConnection` を 1 本張る。シグナリングは同期用の WebSocket に相乗りする。サーバーは `rtc-offer` / `rtc-answer` / `rtc-ice` を宛先へ中継するだけ。

- **参加状態**
  - `PeerInfo.voice` に `off` (不参加) / `muted` (参加・マイク無効) / `on` (参加・マイク有効) を持つ。
  - 変わるたびに `voice` を送ると、サーバーが `peer-update` で全員に配る。
  - 途中参加者には `welcome` のスナップショットで渡る。
  - マイクの許可と `AudioContext` の再開にはユーザー操作が要る。そのため HUD か手首パネルのボタンで参加する。マイクが使えなければ「聞くだけ」(`muted`) で参加する。
- **接続の張り方** (`VoiceMesh`。ネイティブクライアントも同じ規則に従えば相互に話せる)
  - 接続するのは、自分も相手も `voice !== 'off'` のときだけ。
  - offer を出すのは **id が小さい (文字列比較) 側**。両側から同時に offer する衝突 (glare) が起きない。
  - **再交渉はしない**。offer 側が最初から `sendrecv` の音声トランシーバを 1 本だけ作る。
    - マイクの付け外しは `replaceTrack`、ミュートは `track.enabled = false` で行う。SDP は変わらない。
  - SDP と ICE の処理は、接続ごとのキューで順番に実行する。リモートの SDP より先に届いた ICE 候補は取っておく。
- **張り直し**
  - 相手が音声を切った・退出した (`peer-leave`) → 接続を閉じる。
  - 自分の WebSocket が切れた → 全部閉じる。再接続すると id が変わり、相手も古い id との接続を捨てるため。
    - 再接続の `hello` に現在の `voice` を載せるので、参加状態は保たれる。`welcome` で張り直す。
  - `failed`、`disconnected` が 5 秒続いた、または 20 秒つながらない → offer 側が間隔を空けて (1, 2, 4… 最大 15 秒) 作り直す。
  - 新しい offer を受けた側は、その相手との古い接続を捨てる。
- **空間音声** (`src/sync/avatars.ts`)
  - 受信したストリームを、相手のアバターの頭に付けた `PositionalAudio` から鳴らす。
    - HRTF、距離減衰は inverse (`refDistance` 1 m)、正面が強い指向性。
  - 聞き手 (`AudioListener`) はカメラに付ける。XR 中も three.js がカメラを頭の姿勢に合わせるので、そのまま追従する。
  - Chrome では、リモートの WebRTC ストリームを Web Audio に流すために、ミュートした `<audio>` 要素にも繋いでおく。
  - 同室 (同じ `space` の AR 同士) の相手は肉声が聞こえるので、スピーカーからは鳴らさない (音量 0)。
- **話している人の表示**
  - パンナーの手前 (距離減衰の前) に `AnalyserNode` を付けて音量を測る。名札の縁の光・頭の発光・HUD / 手首パネルの「話し中」に使う。
- ICE サーバーの既定は公開 STUN (`stun:stun.l.google.com:19302`) だけ。TURN はビルド時に `VITE_ICE_SERVERS` (JSON 配列) で渡す。

### 途中参加と再接続

- `welcome` で、参加者・姿勢・オブジェクト・ストロークの全量スナップショットを渡す。
- 再接続した端末は新しいピア ID で入り直し、スナップショットで全状態を作り直す。
- 切断中に掴んでいた物や書きかけの線は、ローカルで破棄する。

## プロトコル (v2)

型の定義は `shared/protocol.ts`、サーバー側の検証は `shared/validate.ts` にある。JSON テキストで送受信する。

| 方向 | メッセージ | 内容 |
|---|---|---|
| C→S | `hello` | `v, room, name, color, device, space, voice?` (最初の 1 回。`voice` は省略すると `off`) |
| C→S | `profile` | XR 開始・終了時に `device`, `space` を更新 |
| C→S | `voice` | 音声の参加状態 `state: off / muted / on` |
| C→S | `rtc-offer` / `rtc-answer` / `rtc-ice` | `to` (宛先ピア id) + `sdp` または `candidate` |
| C→S | `pose` | `{head, hands:[L,R]}` 20 Hz |
| C→S | `grab` / `move` / `release` | オブジェクト操作 |
| C→S | `stroke` / `stroke-pts` / `stroke-end` / `board-clear` | ホワイトボード |
| C→S | `reset-objects`, `ping` | |
| S→C | `welcome` | `self` (席番号つき) + スナップショット |
| S→C | `peer-join` / `peer-update` / `peer-leave` | 参加者の変化 |
| S→C | `pose`, `owner`, `move`, `grab-denied`, `objects` | 同期 |
| S→C | `stroke`, `stroke-pts`, `stroke-end`, `board-clear`, `pong`, `error` | |
| S→C | `rtc-offer` / `rtc-answer` / `rtc-ice` | `from` (送り主ピア id) を付けて中継 |

v1 → v2 の変更点: `PeerInfo.voice`、`voice`、`rtc-*` を追加した。v1 のクライアントは、バージョン違いとして参加を断られる。

### サーバーの防御

- メッセージは 64 KB まで、1 接続あたり毎秒 200 件まで。
- 数値は有限値・範囲内に限る。クォータニオンは正規化する。
- ストロークは 1 ルーム 5000 本、1 本 2 万座標まで。
- SDP は 16 KB、ICE 候補は 1 KB まで。
- `rtc-*` を中継するのは、同じルームで、送り主と宛先の両方が音声に参加しているときだけ。ICE 候補には IP アドレスが入るので、音声に参加していない人には渡さない。
- 送信バッファが 4 MB を超えたクライアントは切断する。再接続すれば状態は戻る。
- 15 秒ごとに ping を送り、応答のない接続は掃除する。

### ネイティブクライアント (Android XR / Unity) との相互運用

プロトコルは JSON over WebSocket なので、Kotlin (OkHttp) や Unity (NativeWebSocket など) からそのまま話せる。

- 座標は右手系・Y 軸が上・メートル単位、クォータニオンは `[x, y, z, w]`。
- Unity (左手系) は送受信のときに `z` を反転し、クォータニオンを `(-x, -y, z, w)` に変換する。
- ネイティブ側でも「ローカル ← 共有」の変換を 1 つ持てば同じルームに入れる。キャリブの式 (`frameFromTwoPoints`) は数行なので移植しやすい。Android XR ネイティブなら Jetpack XR の Anchor を使える。
- ネイティブ同士の同室合わせにだけ QR / マーカー (`XR_ANDROID_trackables_qr_code`) を使う、という使い分けもできる。この場合は、Web 側も同じ 2 点を手でタッチすれば座標系がそろう。

## MR 会議アプリへのロードマップ

優先度の高い順に並べる。

1. **音声** (P2P メッシュと空間音声は実装済み → [音声](#音声-srcvoice))
   - 人数が増える (目安 6 人以上) なら、LiveKit などの SFU に移す。
     - 参加状態 (`voice`) と、アバターの頭に `PositionalAudio` を付ける部分はそのまま使える。
   - P2P でつながらないネットワーク向けに、TURN サーバーを用意する。認証情報はサーバーから短命のものを配る。
   - 同室の参加者のマイクが互いの声を拾い、リモートの人には二重に聞こえる。対策は、同室で 1 本のマイクにまとめるか、近くの人の声を抑える処理を入れること。
2. **認証とルームの権限**
   - `hello` にトークンを載せ、サーバーで検証する。
   - 現在は、ルーム名を知っていれば誰でも入れる。
3. **永続化**
   - Room の状態 (ストローク・配置) を KV や DB に保存する。
   - Room は通信手段に依存しない作りにしてあるので、**Cloudflare Durable Objects (1 ルーム = 1 DO、WebSocket Hibernation)** にほぼそのまま載せられる。
4. **ボードの拡張**
   - Undo、消しゴム、付箋、画像や PDF の貼り付け、ボードの移動・複数化。
   - 文書構造が複雑になったら、ストロークを Yjs (CRDT) に移す。
5. **アバターの改善**
   - 手の関節 (25 点) を量子化して送り、ハンドメッシュで表示する。
   - 口の動き (音量) も表示する。
6. **座標合わせの改善**
   - Quest の永続アンカーで、前回のキャリブを復元する。
   - Quest の実験的 `shared` 空間に対応する。
   - 3 点以上の最小二乗フィットで精度を上げる。
   - キャリブ誤差を確認する UI (相手のコントローラー位置を表示する)。
7. **Android XR ネイティブクライアント**
   - Jetpack XR (Kotlin) で同じプロトコルのクライアントを作る。
   - 3D のアセット・レイアウト定数は `shared/` を正とする。

## 既知の制限

- 音声は STUN だけなので、対称 NAT の間などでは P2P でつながらない (TURN が必要)。
- XR に入ってからマイクの許可を求めると、ヘッドセットによっては許可ダイアログが見えない。XR に入る前に参加しておくのが確実。
- 音声のブラウザでの確認は、PC の Chrome (偽のマイク) で 2〜3 タブまで。参加・ミュート・途中参加・再接続・退出を確かめた。実機のヘッドセットではまだ確かめていない。

- 物理演算は無く、手を離した位置でそのまま止まる。
- XR 内で文字は入力できない。名前やルームは入る前に画面で入力する。
- 実機 (Quest / Android XR) での動作確認はまだしていない。IWER エミュレータでは、コントローラー操作・ペン描画・2 点キャリブ・アンカーまで確認済み。
